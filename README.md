# Loop Parallelization Hint Detector (Flang/FIR)

## Project Overview

This project implements a compiler-time parallel loop dependency analyzer for Fortran programs using FIR (Fortran Intermediate Representation) generated by LLVM Flang.

The objective of the project is to determine whether loops can be safely parallelized by detecting memory conflicts between loop iterations before code generation.

Instead of analyzing the original Fortran source code, the analyzer operates directly on FIR generated by the compiler frontend. Each loop is isolated as an independent analysis unit and processed concurrently using multiple threads.

The analysis focuses on identifying memory access conflicts across loop iterations by tracking memory locations accessed within each loop and comparing them across parallel analysis threads.

---

# Problem Statement

Modern compilers attempt to parallelize loops to improve performance.

A loop can only be parallelized when different iterations do not access conflicting memory locations.

Examples of conflicts include:

```fortran
do i = 2, n
    a(i) = a(i-1) + 1
end do
```

In this example:

```text
Iteration i accesses data produced by iteration i-1
```

Such dependencies prevent safe parallel execution.

The goal of this project is to detect these conflicts during compiler analysis.

---

# Project Objectives

* Analyze FIR generated by LLVM Flang.
* Extract all loop operations represented as `fir.do_loop`.
* Isolate every loop as an independent analysis entity.
* Launch parallel worker threads for loop analysis.
* Track memory locations accessed within each loop.
* Detect memory conflicts between loop iterations.
* Generate compiler hints indicating whether a loop is safe for parallelization.

# Role of Flang in the Project

Flang is responsible for converting Fortran source code into FIR.

The analyzer does not process source code directly.

Instead, Flang produces an MLIR-based FIR representation which contains:

* Loop operations
* Memory accesses
* Arithmetic operations
* Function calls
* Array indexing information

This representation becomes the input to the analyzer.

---

# Role of FIR in the Project

FIR (Fortran Intermediate Representation) contains compiler-level information about program execution.

The analyzer uses FIR operations such as:

```text
fir.do_loop
fir.load
fir.store
fir.array_coor
fir.call
```

These operations provide sufficient information to determine memory access patterns and potential dependencies.

---

# Loop Isolation Strategy

Every detected loop is treated as an independent analysis object.

Example:

```fortran
do i = 1, n
    a(i) = i
end do

do j = 1, n
    b(j) = j
end do
```

The analyzer extracts:

```text
Loop Entity #1
Loop Entity #2
```

Each entity contains:

* Loop identifier
* FIR operations belonging to the loop
* Memory access information
* Analysis metadata

This allows multiple loops to be analyzed simultaneously.

---

# Parallel Analysis Architecture

After loop extraction, a separate worker thread is created for each loop entity.

Architecture:

```text
Loop #1  ---> Thread 1
Loop #2  ---> Thread 2
Loop #3  ---> Thread 3
Loop #4  ---> Thread 4
```

Threads execute concurrently.

The purpose of multithreading is to simulate compiler-time dependency analysis at scale while reducing total analysis time.

---

# Memory Tracking Mechanism

The analyzer tracks memory locations referenced by FIR operations.

Example FIR operations:

```text
fir.load
fir.store
fir.array_coor
```

For every access:

1. Memory address is identified.
2. Address is stored using pointer-based tracking.
3. Read and write operations are recorded.
4. Access information is shared with conflict detection logic.

Conceptually:

```cpp
MemoryAccess {
    void* address;
    bool isRead;
    bool isWrite;
}
```

The analyzer focuses on whether multiple loop iterations reference the same memory location.

---

# Conflict Detection Algorithm

The analyzer compares memory locations collected by parallel worker threads.

If two accesses reference the same memory location and at least one access performs a write operation:

```text
Read + Write
Write + Read
Write + Write
```

A dependency is reported.

Example:

```fortran
do i = 2, n
    a(i) = a(i-1)
end do
```

Detected Conflict:

```text
Thread A -> Accesses a(i)
Thread B -> Accesses a(i-1)

Memory overlap detected
```

Result:

```text
Loop Not Safe For Parallelization
```

---

# Classification Rules

## Safe

Conditions:

```text
No overlapping memory accesses detected
No conflicting writes detected
No dependency identified
```

Output:

```text
Likely Parallelizable
```

---

## Unsafe

Conditions:

```text
Shared memory location detected
Loop-carried dependency detected
Write-after-write conflict detected
Read-after-write conflict detected
Write-after-read conflict detected
```

Output:

```text
Not Safe
```

# Build Instructions

```bash
mkdir build
cd build
```

Configure project:

```bash
cmake -G Ninja \
-DMLIR_DIR=<LLVM_BUILD>/lib/cmake/mlir \
-DLLVM_DIR=<LLVM_BUILD>/lib/cmake/llvm \
..
```

Compile:

```bash
ninja -j4
```

---

# FIR Generation

Generate FIR from a Fortran source file:

```bash
flang-new -fc1 -emit-fir ../tests/sample.f90 -o ../tests/sample.mlir
```

The generated FIR file becomes the input to the analyzer.

---

# Running the Analyzer

```bash
./detector ../tests/sample.mlir
```

# Conclusion

This project demonstrates compiler-time loop dependency analysis using FIR generated by LLVM Flang.

By isolating each loop into a separate analysis entity, executing analysis in parallel threads, and tracking memory locations through pointer-based access records, the system detects memory conflicts that may prevent safe loop parallelization.

The generated classification assists compiler optimization passes in identifying loops that are likely safe or unsafe for parallel execution.
